# Glossary

One meaning per term. If a word is used differently anywhere in the repo, the repo is wrong.

| Term | Meaning |
|---|---|
| **Reader** | Who the site is for: senior, staff and principal engineers, tech leads and engineering managers who want to use AI well in daily work. |
| **Track** | One subject taught end to end, for example Context Engineering. A track is an ordered list of lessons. |
| **Lesson** | One chapter of a track. One sitting, one main idea, about five minutes. Has its own page. |
| **Beat** | One screen-sized step inside a lesson: a few sentences, usually with one drawing. A lesson is a sequence of beats. |
| **Drawing** | A hand-drawn animated explainer (GIF or video loop) that plays inside a beat. |
| **Check** | One short question at the end of a beat or lesson that lets the reader test the idea. |
| **Lab** | A runnable experiment with real, recorded results that proves a claim made in a lesson. |
| **Short** | A vertical video under 60 seconds made from one lesson, for YouTube Shorts and Instagram Reels. It points back to the lesson. |
| **Roadmap** | The single file that lists every track and lesson, their order and their status. The site's table of contents is generated from it. |
| **Status** | Where a track or lesson stands: `live`, `in-progress` or `planned`. Planned items are shown quietly, not hidden. |
| **Raw notes** | Vikas's handwritten notes as shared (PDF plus extracted text), stored by date. The source of truth for content. |
| **Pipeline** | The steps that turn raw notes into site updates, drawings, labs and Shorts. |
| **Proposal** | The pipeline's plan for one batch of notes: what will be added or changed. Nothing is built until Vikas approves it. |
| **Changelog** | The dated "What's new" list on the site, written by the pipeline at each publish. |
| **ADR** | Architecture Decision Record. One short file per decision in `docs/adr/`. |
